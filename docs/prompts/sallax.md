> (177 ملف Dart، 15 feature، وشاشات ليها نسخة موبايل ونسخة ديسكتوب). الوصف الحالي
> بيقول 4 مميزات بس، والمفروض يبقى Case Study كاملة زي «سنتر المفيد» و«نقاط البيع».

```
اقرأ المشروع ده كله الأول، وبعدين جهّزلي مادة كاملة عشان أعرضه في البورتفوليو بتاعي
كـ Case Study محترمة. المطلوب حاجتين: لقطات شاشة منظّمة + ملف محتوى شامل.

المشروع تطبيق تجارة إلكترونية اسمه "سلة / SallaX" مبني بـ Flutter.
اللي شفته في الكود: 15 feature (onboarding, splash, auth, home, search, offers,
coupons, cart, checkout, address, payment, orders, wishlist, profile, layout)،
والستاك فيه flutter_bloc + get_it + freezed + go_router + dio مع JWT وsecure storage،
وflutter_map (OpenStreetMap) للعناوين، وflutter_stripe للدفع، وsqflite للتخزين المحلي.
كمان في شاشات ليها نسخة ديسكتوب ونسخة موبايل منفصلة (responsive) — دي نقطة مهمة.
أكّد كل ده بنفسك من الكود، ولو في حاجة فهمتها غلط صحّحها.

اشتغل بالترتيب ده:

═══════════════════════════════════════════
1) افهم المشروع فعليًا
═══════════════════════════════════════════
• اقرأ الـ features كلها والـ blocs/cubits وطبقة الـ data والـ core.
• اطلعلي بقائمة بكل شاشة وإيه اللي بتعمله بالظبط.
• ركّز على الحاجات اللي فيها شغل تقني حقيقي وقوللي بتشتغل إزاي:
   - الـ auth: JWT + refresh + التخزين الآمن + شاشة الـ OTP ونسيت كلمة السر
   - الـ responsive: الشاشات اللي ليها نسخة desktop ونسخة mobile — إزاي بتتقرر النسخة
   - الخرايط: flutter_map + geolocator + geocoding وإدارة صلاحيات الموقع
   - الدفع: Stripe — إيه اللي متعمول بالظبط وإيه اللي test mode
   - الكاش المحلي: sqflite بيخزّن إيه بالظبط وإمتى
   - الكوبونات والعروض: منطق الخصم شغّال إزاي
• مهم جدًا: قوللي إيه المتعمول فعلًا وإيه الناقص أو نصف شغّال. أنا مش عايز أكتب
  في البورتفوليو حاجة مش موجودة، وكمان لو في حاجة كبيرة متعمولة ومش معروضة عايز أعرف.

═══════════════════════════════════════════
2) جهّز بيانات تجريبية محترمة
═══════════════════════════════════════════
• مفيش شاشة فاضية ولا Loading ولا "No data" في أي لقطة.
• منتجات وأسعار وتصنيفات وصور واقعية (بالجنيه المصري)، وصور منتجات حقيقية مش رمادي.
• السلة فيها 3 منتجات بكميات مختلفة وكوبون خصم متطبّق عشان يبان الحساب.
• المفضلة فيها 4–6 منتجات، والطلبات فيها طلب قيد التنفيذ وطلب متسلّم.
• ثبّت نفس المستخدم ونفس العنوان ونفس التاريخ في كل اللقطات.
• متستخدمش بيانات حقيقية (تليفونات، إيميلات، كروت) — كله مولّد، والدفع test mode.
• لو محتاج حساب تجريبي، اعمل واحد وقوللي بياناته في الآخر.

═══════════════════════════════════════════
3) صوّر اللقطات — موبايل + ديسكتوب
═══════════════════════════════════════════

أولًا: لقطات الموبايل (طولية)
• Android emulator بمقاس ثابت 1080×2340، نفس المقاس لكل اللقطات.
• صوّر بـ: adb exec-out screencap -p > <filename>.png
• نضّف شريط الحالة الأول عشان اللقطات تبقى شكلها احترافي:
    adb shell settings put global sysui_demo_allowed 1
    adb shell am broadcast -a com.android.systemui.demo -e command clock -e hhmm 1200
    adb shell am broadcast -a com.android.systemui.demo -e command battery -e level 100 -e plugged false
    adb shell am broadcast -a com.android.systemui.demo -e command network -e wifi show -e level 4
    adb shell am broadcast -a com.android.systemui.demo -e command notifications -e visible false
  (وفي الآخر: adb shell am broadcast -a com.android.systemui.demo -e command exit)

  01-home                الرئيسية — التصنيفات والمنتجات (دي صورة الغلاف، خليها أقوى لقطة)
  02-product-details     تفاصيل المنتج
  03-search              البحث والفلاتر
  04-cart                السلة بمنتجات وحساب الإجمالي
  05-coupon              تطبيق كوبون خصم والإجمالي بعد الخصم
  06-checkout            مراجعة الطلب قبل الدفع
  07-address-map         اختيار عنوان التوصيل على الخريطة (OpenStreetMap)
  08-my-addresses        قائمة العناوين المحفوظة
  09-payment             شاشة الدفع وبيانات الكارت
  10-payment-success     تأكيد نجاح الدفع
  11-orders              الطلبات وحالتها
  12-wishlist            المفضلة
  13-offers              العروض
  14-profile             الملف الشخصي والإعدادات
  15-login               تسجيل الدخول
  16-otp                 تأكيد الكود (OTP)
  17-onboarding          شاشات التعريف

ثانيًا: لقطات الديسكتوب (عرضية) — دي اللي هتوري إن التطبيق responsive
• شغّل نسخة الويب أو الويندوز بمقاس ثابت 1600×900 وصوّر الشاشات اللي ليها نسخة ديسكتوب:

  18-desktop-home        الرئيسية بتخطيط الشاشة الكبيرة
  19-desktop-product     تفاصيل المنتج ديسكتوب
  20-desktop-cart        السلة ديسكتوب
  21-desktop-checkout    الشيك أوت ديسكتوب

قواعد عامة:
• نفس الثيم في كل اللقطات (متخلطش دارك ولايت).
• PNG محسّنة الحجم — الموبايل تحت 400KB والديسكتوب تحت 300KB.
• من غير مؤشر ماوس ومن غير شريط المتصفح في لقطات الديسكتوب.
• لو في bottom sheet أو dialog مهم، صوّره وهو مفتوح فوق الشاشة اللي وراه.

حط كل الصور في مجلد `portfolio-shots/` في جذر المشروع بالأسماء دي بالظبط + .png

═══════════════════════════════════════════
4) ملف portfolio-shots/portfolio.md
═══════════════════════════════════════════
اكتب فيه الحاجات دي، وكل حاجة **بالعربي والإنجليزي** مع بعض:

أ)  اسم المشروع الطويل + اسم مختصر للكارت.
ب)  وصف قصير للكارت (حوالي 30 كلمة).
ج)  وصف أطول لصفحة التفاصيل (3–4 أسطر).
د)  نبذة عن المشروع (فقرتين): المعمارية (feature-first)، إدارة الحالة بـ Bloc،
    الـ DI بـ get_it، التوجيه بـ go_router، وطبقة الشبكة والكاش.
هـ) المشكلة اللي بيحلها (2–3 فقرات) — ابدأ بمشكلة حقيقية في السوق مش بقايمة مميزات.
و)  دوري في المشروع (فقرة): عملت إيه بالظبط، والباك اند جه منين.
ز)  التحديات وأصعب جزء تقني (فقرتين) — من واقع الكود. لو الـ responsive أو دورة
    الدفع أو الـ auth كانوا أصعب حاجة، اتكلم عنهم بالتحديد.
ح)  المميزات الرئيسية: 14–18 ميزة، كل واحدة بالشكل ده بالظبط:
        <إيموجي> <عنوان قصير> — <شرح سطر أو اتنين>
    مثال: 🗺 اختيار العنوان على الخريطة — تحديد موقع التوصيل بدقة عبر OpenStreetMap مع حفظ العناوين المتكررة.
ط)  التقنيات مقسّمة لمجموعات، مثلًا:
        الواجهة / إدارة الحالة والتوجيه / الشبكة والمصادقة / الخرايط والدفع / التخزين والأدوات
ي)  كابشن لكل لقطة بالترتيب بالعربي والإنجليزي، وجنبه اسم الملف.
ك)  الروابط: رابط الريبو (github.com/taha2901/ECE)، لينك الـ APK، لينك فيديو الديمو.
ل)  الحالة المناسبة: Production / Live Demo / Offline / Design Only + جملة توضّحها.

═══════════════════════════════════════════
5) أرقام المشروع (بأوامر فعلية مش تخمين)
═══════════════════════════════════════════
احسبلي وحط جنب كل رقم الأمر اللي استخدمته:
• عدد الشاشات
• عدد الـ features
• عدد ملفات Dart
• عدد أسطر الكود
• عدد الـ Widgets
• عدد الـ Blocs/Cubits
• عدد الـ API endpoints المستخدمة
• عدد الشاشات اللي ليها نسخة responsive منفصلة
• عدد الاختبارات الآلية (لو مفيش قول "لا يوجد" بصراحة)
لو رقم مش متاح اكتب "غير متاح" — بلاش تقديرات.

═══════════════════════════════════════════
ملاحظات أخيرة مهمة
═══════════════════════════════════════════
• متكتبش أي ميزة مش موجودة فعلًا في الكود. لو حاجة نصف مكتملة قول كده صراحة.
• لو مقدرتش تصوّر شاشة معيّنة (محتاجة باك اند شغّال مثلًا)، قوللي الشاشة وليه وكمّل الباقي.
• في الآخر اعرضلي قائمة بكل الملفات اللي اتولدت وحجم كل واحد.
```
